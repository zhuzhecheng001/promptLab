# promptLab 使用说明

promptLab 是一个"造 Skill 的 IDE"。你可以用自然语言向 AI 描述你想要一个什么样的 AI 助手（Skill），AI 帮你撰写提示词和规范文档，然后你直接在另一个对话框里和这个"造出来的 AI"对话，检查它表现如何、不断调试改进。

## 1. 登录

- promptLab 使用个人站（zhecheng.fun）账号登录，**无需单独注册**。
- 首次打开页面如果提示登录，点击"前往个人站登录"，登录完成后回到 promptLab 刷新即可。
- 每个人的项目、文件、对话记录和模型配置都是**互相隔离**的，各看各的。

## 2. 界面一览

打开后是四块区域：

```
┌────────────┬───────────────────────┬─────────────┐
│            │                       │   工匠台     │
│  文件管理器  │       编辑器           ├─────────────┤
│            │                       │   测试台     │
└────────────┴───────────────────────┴─────────────┘
```

| 区域 | 作用 |
|---|---|
| 文件管理器（左） | 查看当前项目的文件结构，新建 / 重命名 / 删除文件，切换项目 |
| 编辑器（中） | 编辑选中文件的文字内容，支持 Markdown 预览和高亮 |
| 工匠台（右上） | 和"工匠"AI 对话：向它描述需求，它帮你撰写提示词和文档，并可直接写入文件 |
| 测试台（右下） | 和"执行者"AI 对话：执行者会加载当前项目的 Skill 文档，按它扮演的角色与你对话，用来检查效果 |

顶栏右侧：新建项目、模型设置、状态提示、用户名。

## 3. 基本流程

**第一步：新建项目**

点击顶栏"新建项目"，输入名称（如"周报助手"）。系统会自动创建一套标准文件骨架。

**第二步：准备 Skill 内容**

两种方式，可以混用：

- **手动写**：在文件管理器点击文件（如 `SKILL.md`），在编辑器里直接写提示词和规范。
- **让 AI 写**：在工匠台描述你的需求，例如"我要一个帮我把本周工作整理成周报的助手，语气简洁"，工匠会生成内容并可以写入项目文件。

**第三步：测试效果**

在测试台直接和执行者对话，例如"我本周做了三件事：……帮我写周报"。执行者会根据你写的 Skill 文档来回答。

**第四步：调试迭代**

如果执行者的回答不符合预期（语气不对、格式不对、不知道该做什么）：

1. 回到编辑器，修改 `SKILL.md` 或规范文档里的描述；
2. 修改后，测试台会自动开启新一轮对话（旧对话保留，方便对比）；
3. 再测试，直到满意。

> 小提示：发消息时系统会先自动保存你正在编辑的文件，不用手动点保存。

## 4. 文件管理

- **项目**：顶栏"新建项目"创建；左侧项目列表每行有"重命名项目""导出项目""删除"按钮；删除不可恢复，请谨慎。
- **文件**：左侧文件树支持新建、重命名、删除。删除文件前会自动保存一份快照（存在项目快照目录），如果误删可在快照目录找回。
- **导出**：可以把整个项目打包下载（zip），方便备份或分享。

## 5. 模型设置

点击顶栏"模型设置"，有三个配置板块：

| 板块 | 作用 |
|---|---|
| 作者的 API（公共接口） | 网站作者提供的公共模型接口，默认 DeepSeek |
| 工匠 | 负责撰写提示词和文档的 AI 模型 |
| 执行者 | 测试台里和你对话的 AI 模型 |

每个板块可以填三项：**Base URL**、**API Key**、**模型名**。

**借用作者的 API**：勾选后，该角色直接调用上方"作者的 API"，你不需要填 key。不勾选，则使用下方你自己的配置（适合想测试不同模型效果的人）。

> 安全说明：API Key 保存后不会回显，输入框留空表示"保持已保存的 key 不变"。请勿把 key 分享给他人。

## 6. 常见问题

**问：为什么我改了文档，执行者还是按老样子回答？**
修改文件后，测试台会自动开启新会话，在新会话里提问即可。如果仍感觉没生效，确认已保存文件（发消息会自动保存）。

**问：执行者不认识我是谁 / 回答很奇怪？**
在 `SKILL.md` 里把角色设定写清楚：身份、职责、语气、回复格式、禁忌。写得越具体，执行者表现越稳定。

**问：如何让执行者能看到我的个人信息？**
可以在项目文档里（如 `notes.md`）写入你想让它知道的背景信息，然后在新会话中提问。

**问：工匠写的内容怎么进到文件里？**
在工匠台生成内容后，点击回复下方的"写入 SKILL.md"按钮即可。之后可以在编辑器里查看和修改。

**问：页面提示未登录 / 401？**
说明登录态过期了，点击"前往个人站登录"，登录后回来刷新页面。

**问：Skill 文档必须叫 SKILL.md 吗？文件格式必须是 Markdown？**
建议核心提示词放在 `SKILL.md`。你也可以在项目里添加其他 Markdown 文件作为补充规范，执行者会一起加载。目前主要支持 Markdown 格式文本文件。

## 7. 小建议

- Skill 提示词写得**具体**：给例子、给格式、给禁忌，比"你是一个助手"管用得多。
- 每次改完文档，在测试台开新会话验证一次，形成"写→测→改"的循环。
- 项目文件就是普通文本，随时可以导出备份。

# PromptLab MVP 功能清单（v0.1）

> 一句话定位：一个"造 Skill 的 IDE"——AI1 工匠负责写 skill，AI2 执行者负责试跑，你（用户）在中间当质检员。AI3 自动质检留到阶段 2。

---

## 一、三 AI 角色（同一个 LLM 后端，三套角色提示词）

| 角色 | 职责 | 模型来源 | 阶段 |
|---|---|---|---|
| AI1 工匠 | 接收你的需求 → 撰写 SKILL.md + 规范文档 | 内置 DeepSeek | MVP |
| AI2 执行者 | 加载 skill → 与你对话试跑（模拟真实 Agent 使用 skill） | **用户自定义**：填 base_url + api_key + model | MVP |
| AI3 质检 | 旁听你与 AI2 的对话 → 自动找偏差、提修改建议 | 内置 DeepSeek | MVP 开发（可选功能）→ 阶段 2 验收 |
| （AI3 终极形态） | 自动与 AI2 对练 → 判断 skill 是否合理 → 自动修改 → 回归验证 | 内置 DeepSeek | 阶段 3 |

关键约定：
- 三个角色**不是三个模型**，是同一个模型 API 下的三套 system prompt（工匠人设 / 执行者人设 / 质检人设）。
- AI2 支持用户自定义模型：统一走 **OpenAI 兼容格式**（DeepSeek、豆包、智谱、OpenAI 等均兼容），用户只需填 base_url、api_key、model 三个字段。
- AI2 可换模型 = 同一个 skill 可以跨模型试跑，是产品的特性（调试"模型兼容性"）。

## 二、前端四块（对应 IDE 布局）

### ① 文件管理器（左）
- 项目列表：新建 / 切换 / 删除 skill 项目
- 文件树：SKILL.md、规范文档.md、资产/（脚本、模板、示例）
- 新建 / 重命名 / 删除文件
- MVP 简化：不做拖拽、不做搜索、不做图标主题

### ② 工匠对话台（右上，AI1）
- 输入需求："帮我做一个写周报的 skill，要求……"
- AI1 生成产物：SKILL.md + 规范文档（流式输出）
- **一键落盘**：生成的产物写入文件树，编辑区自动刷新
- 后续修改指令："把第 3 条改成……"（AI1 在项目上下文内修改）
- MVP 简化：不支持多文件同时生成时的复杂编排，先支持"一个 skill 一套文件"

### ③ 编辑区（中）
- 查看 / 编辑任意文件（MVP 用普通文本框即可，不做语法高亮）
- 保存按钮：保存前**自动生成一份快照**（版本回退的保险）
- 底部：资产文件标签页切换
- MVP 简化：不做 diff、不做折叠、不做自动补全

### ④ 测试对话台（右下，AI2）
- 选择要测试的 skill 项目
- **模型设置**：填 base_url + api_key + model（AI2 专用，用户自备 key）
- 加载 skill 后开始对话（AI2 上下文 = 基础执行者人设 + 当前 skill 内容）
- "重新加载"按钮：编辑区保存后，点击让 AI2 使用最新版 skill
- **"转给工匠"按钮**：把 AI2 的一条坏回答转给工匠台，作为修改需求（不用复制粘贴）
- **"让 AI3 分析"按钮（可选，MVP 不验收）**：把这段对话交给 AI3，返回偏差分析与修改建议；默认不开启
- MVP 简化：不做多轮上下文分支、不做并发测试

### 三条联动（IDE 的灵魂）
1. 工匠产出 → 自动落盘文件树 → 编辑区刷新
2. 编辑区保存 → 测试台提示"已保存，点击重新加载"
3. 测试发现坏回答 → 一键转给工匠台

## 三、后端模块（最小可用）

1. **LLM 客户端**：OpenAI 兼容封装，支持 stream；三个角色各有一份 system prompt 模板
2. **skill 渲染器（核心函数）**：把 skill 文件渲染成 AI2 的系统提示词
   ```
   render_runner_prompt(skill) =
       基础执行者人设 + 【当前技能】+ SKILL.md 全文 + 规范文档摘要
   ```
3. **文件管理 + 快照**：读写项目文件；每次保存前自动存快照（时间戳命名）
4. **对话 API**：AI1 / AI2 对话接口，SSE 流式返回
5. **AI3 质检接口（MVP 就写好，可选）**：接收一段对话记录 → 返回偏差分析与修改建议。MVP 不验收，界面做成可选按钮，默认不开启
6. **用例记录**：把"用户标记的好回答 / 坏回答"存库 —— AI3 的尺子（建议质量依赖用例积累，用例来自 MVP 阶段你的手动标注）

## 四、数据存储（MVP）

| 内容 | 存储方式 |
|---|---|
| skill 项目文件 | 本地文件系统（磁盘目录） |
| 项目元数据、对话记录、快照、用例 | SQLite |

---

## 五、安全注意（重要）

- AI2 的 API key 是用户的敏感信息：本地存储，界面不展示明文；提醒用户 key 自备、自担风险
- 不做服务端代理转发到第三方：学习项目本地跑，key 不离开本机（除直接调用用户填写的 API）

## 六、阶段路线

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **1 · MVP（本文）** | AI1 写 skill → AI2 对话试跑 → 你发现问题（自己改 / 让 AI1 改）。AI3 后端已写好、前端为可选按钮，**不参与验收** | 用"写周报"需求跑通：AI1 产出 → 落盘 → AI2 按 skill 回答 → 转工匠改一轮 |
| 2 · 进阶 | AI3 旁听对话，自动提修改建议 | AI3 能对一轮对话给出≥1条有效建议 |
| 3 · 终极 | AI3 自动与 AI2 对练 → 判定 → 自动修改 → 回归 | 对同一需求，AI3 自动迭代 N 轮后 skill 通过你预置的用例集 |

---

## 七、部署路线（先网页版，再桌面版）

| 步骤 | 形态 | 技术方案 | 说明 |
|---|---|---|---|
| 1 | 网页版 | React 前端 + FastAPI 后端，本地运行或自部署 | 先验证产品价值；MVP 阶段定位本地运行/自部署，不做公网多人注册（API key 安全最简单） |
| 2 | Windows 桌面版 | Electron 壳 + 打包的本地 FastAPI 后端（PyInstaller） | 前端/后端代码 100% 复用，只加一个壳；skill 文件与 key 都留在本机，离线可用 |
| 3 | macOS 桌面版 | 同一套 Electron 代码，换平台打包 | Windows 版稳定后再出 |

关键设计：
- **前端代码一套，三端复用**：浏览器 / Electron-Windows / Electron-macOS 跑的是同一个 React 应用
- **后端代码一套**：网页版部署在服务器；桌面版把 Python 后端打包进应用本地跑（Electron 启动时拉起本地 FastAPI）
- 桌面版是产品的完整形态（文件、key 都在本机）；网页版是轻量试用入口

# 后端最小接口设计（v0.1）

> 配套文档：`MVP功能清单.md`。本文件只定义 MVP 需要的接口，与具体语言无关。

---

## 一、技术选型建议

| 层 | 建议 | 理由 |
|---|---|---|
| 后端框架 | Python + FastAPI | AI 项目生态最成熟，DeepSeek 官方 SDK/文档齐全，stream 支持好 |
| 数据库 | SQLite | 零配置，够 MVP |
| 文件存储 | 本地文件系统 | skill 就是文件夹，直接落盘最直观 |
| 前端框架 | Vue 3 或 React（二选一） | 都不错，学习项目选你更愿意学的那个 |

> 若你更熟 JavaScript，后端也可用 Node.js + Express 实现，**接口保持不变**。

---

## 二、模型配置

### 内置模型（AI1 工匠 / AI3 质检）
- 当前：DeepSeek（你额度还没用完，先用它）
- 放在后端配置文件（`.env` 或 `config.json`），后续可替换

### 用户自定义模型（AI2 执行者）
- 前端填三个字段，保存到本地：
  ```
  base_url  （如 https://api.deepseek.com）
  api_key   （用户自己的 key，本地存储，界面不明文展示）
  model     （如 deepseek-chat）
  ```
- 统一走 OpenAI 兼容格式，所以任意兼容提供商都能填

---

## 三、skill 渲染器（核心函数）

AI2 的每次对话，系统提示词 = 固定人设 + 当前 skill 内容：

```
render_runner_prompt(skill) =
  【执行者人设】你是一个按技能说明工作的 AI 助手……
  【当前技能】
  （SKILL.md 全文）
  【技能规范摘要】
  （规范文档.md 的前 N 段或全文）
```

- skill 文件变更后，AI2 需要"重新加载"才会使用新内容（前端提供按钮）
- 这个函数是全项目的心脏，其它接口都围绕它

## 四、接口列表

### 1. 项目管理
| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/projects` | 新建项目 `{name}` → 创建目录骨架（SKILL.md、规范文档.md、资产/） |
| GET | `/api/projects` | 项目列表 |
| GET | `/api/projects/{id}` | 项目详情（名称、文件树） |

### 2. 文件操作
| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/projects/{id}/files` | 文件树（递归列出） |
| GET | `/api/files/{path}` | 读取文件内容 |
| PUT | `/api/files/{path}` | 保存文件内容（**保存前自动生成快照**） |
| POST | `/api/projects/{id}/snapshots` | 手动创建快照 |
| GET | `/api/projects/{id}/snapshots` | 快照列表（可回退查看） |

### 3. 对话（SSE 流式）
| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/chat/builder` | AI1 工匠对话。请求：`{project_id, message}`；响应：流式输出 SKILL.md/文档 |
| POST | `/api/chat/runner` | AI2 执行者对话。请求：`{project_id, message, model_config}`；响应：流式回答 |
| GET | `/api/conversations/{id}/messages` | 拉取某段对话的历史消息 |

> 所有对话接口都用 SSE（Server-Sent Events）流式返回，前端打字机效果。

### 4. 用例记录（为 AI3 铺路）
| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/test-cases` | 记录一条用例：`{project_id, user_message, ai2_reply, verdict: good/bad, note}` |
| GET | `/api/test-cases?project_id=` | 拉取某项目的用例列表 |

> 阶段 1 就启用：你在测试台每标记一次"这个回答不行"，就存一条。将来 AI3 的判定标准 = 需求清单 + 这些用例。

### 5. 模型设置
| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/settings/runner-model` | 读取 AI2 的模型配置（key 打码返回） |
| PUT | `/api/settings/runner-model` | 保存 AI2 的模型配置 |

## 五、技术要点

- **SSE 流式**：对话接口一律 stream，前端逐字显示，体验好且不阻塞
- **快照**：保存文件时自动快照（`SKILL.md.2026-10-14-1530.md`），改坏了能找回
- **用例是资产**：从 MVP 第一天开始积累，它们决定阶段 3 的自动质检质量
- **AI1 的上下文**：工匠对话要带项目上下文（当前 SKILL.md 内容），改需求时它才知道改哪里

## 六、MVP 验收场景（写周报 skill）

1. 新建项目"周报助手" → 自动生成文件骨架
2. 工匠台：输入"帮我做一个写周报的 skill，要求覆盖本周工作、下周计划、风险" → AI1 生成 SKILL.md → 一键落盘
3. 测试台：填 DeepSeek 的 base_url/key/model → 加载"周报助手" → 对话"帮我写这周周报，这周做了 A 和 B"
4. 发现回答跑偏 → 点"转给工匠" → 工匠台收到修改需求 → AI1 修改 → 落盘
5. 编辑区：保存任意文件 → 测试台点"重新加载" → 再测
6. 标记一条"好回答/坏回答"用例 → 存入 SQLite
